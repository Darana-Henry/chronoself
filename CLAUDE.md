# ChronoSelf

Personal life-tracking dashboard hosted on Firebase. A collection of standalone HTML pages — no framework, no bundler, no runtime dependencies beyond Firebase.

## Architecture

**Pure static site.** Every page is a single self-contained HTML file with all CSS and JS inline. No npm packages at runtime. No build transpilation — the build step is only a string-replace for Firebase config injection.

**Hosting:** Firebase Hosting (`chronos-self.web.app`). The `dist/` folder is what gets deployed — never edit files there directly.

**Data persistence:**
- Primary: `localStorage` (keys prefixed `chrono_`)
- Optional cloud backup: Firestore under `users/{uid}/` — triggered manually via the "Sync to Firebase" button on the landing page
- Instagram follower history: `data/instagram.json` committed to the repo, served as a static asset at `/data/instagram.json`
- School Finder data: `data/schools.xml`, served at `/data/schools.xml`
- Reboot 50-day plan logs: `chrono_reboot` (array of `{date, done, steps, kcal, protein, weight, note}`), Firestore `users/{uid}/data/reboot`
- India map: `data/india-map.json` (state outlines as projected SVG paths, generated by `scripts/build_india_map.js`) `data/india-states.json` (capitals, CM, party, seat counts, and the `parties` table of names, alliances and chart colours — edit by hand when a CM changes) and `data/india-elections.json` (seats won per party at each state's latest Assembly election and the 2024 Lok Sabha election — static, hand-curated; when a state votes, replace its `assembly` entry)
- India government posts: `data/india-government.json` — Union PM/Home/Finance/Defence/External Affairs holders for the last five governments (`union`, newest first; a post that changed hands mid-term lists every holder with `since`/`until`), each person's home state and seat (`people`), and each state's Governor/LG, Deputy CMs, Home and Finance ministers (`states`; `"cm"` means the CM holds it). Static and hand-curated like the election files — edit when a minister changes
- Telangana explainer: `data/india-telangana.json` — intro, scoreboard bars (`rows` are `[party, seats, label?, tip?]`; `XBRS`, `RAJA`, `VAC`, `OTH` are special colours), government, parties, dated `timeline` (tag: Background/Election/Government/Party/Courts/Probe), `faultLines` and `watch`. Hand-written from news reports; update `asOf` when editing
- Minute Cryptic clues: `data/minute-cryptic.json`, served at `/data/minute-cryptic.json`; play progress in `chrono_cryptic` and Firestore `users/{uid}/data/cryptic`

## Build

```bash
node scripts/inject.js          # reads .env.qa, writes dist/
```

`inject.js` replaces `__PLACEHOLDER__` tokens in each HTML file with real Firebase config values and copies `data/` → `dist/data/`. Requires these env vars (in `.env.qa` locally, GitHub secrets in CI):

```
FIREBASE_API_KEY
FIREBASE_AUTH_DOMAIN
FIREBASE_PROJECT_ID
FIREBASE_STORAGE_BUCKET
FIREBASE_MESSAGING_SENDER_ID
FIREBASE_APP_ID
OWNER_UID            # optional; only needed to build build/firestore.rules
```

Never commit `.env.qa` — it is gitignored.

## Deploy

```bash
node scripts/inject.js && firebase deploy --only hosting
```

## Private config and access

Nothing personal is hard-coded in the pages. The weekly schedules (`BLOCKS`, `BLOCKS2`), tracker habits (`ACTIVITIES`), default goals (`DEFAULT_GOALS`) and the Classes timetable (`CLASSES`) are loaded at startup from `chrono_config` in `localStorage`, which `fsPull` fills from Firestore `users/{uid}/data/config` (stored as a `json` string field). The source file is `private/chronoself-config.json` (gitignored). To change it, edit that file and open `schedule.html?setup=1` to re-import; a first visit with no config shows the same import screen.

Access is enforced by Firestore rules, not by the pages: `firestore.rules` admits only the owner's uid (`__OWNER_UID__`, filled from the `OWNER_UID` env var into `build/firestore.rules` by `inject.js`). Pages sign in with Google and treat a `permission-denied` on their first Firestore read as "not the owner". Deploy rules manually:

```bash
node scripts/inject.js && firebase deploy --only firestore:rules
```

## Coding conventions

- **All CSS and JS inline** in the HTML file — no external `.css` or `.js` files
- **No chart libraries** — charts are drawn with vanilla SVG via `document.createElementNS`
- **No comments** unless the why is non-obvious
- **Dark theme** throughout: background `#0a0a0a`, text `#e8eaed`, grid overlay via `body::before`
- CSS custom properties defined at the top of `schedule.html`: `--txt`, `--txt-mid`, `--txt-dim`, `--line`, `--tab-h`
- Accent colours by feature: blue `#5b8eff` (schedule), green `#4ddd8e` (tracker), purple `#a06bff` (backlog), yellow `#ffc84d` (goals), orange `#ff8050` (freeletics), pink `#ff8fab` (chronicle), violet `#c97aff` (classes), red `#f87171` (Reboot), violet `#c084fc` (Instagram), teal `#2dd4bf` (Minute Cryptic), lime `#a3e635` (Library), sky `#38bdf8` (School Finder), indigo `#818cf8` (India)

## Instagram Tracker

Tracks follower counts for three public accounts daily:
- `hankcuratesfilms`
- `hanklosesweight`
- `hankcuratesarchive`

**Automated collection:** `.github/workflows/instagram_tracker.yml` runs at 00:05 IST (18:35 UTC) daily.

Workflow steps:
1. `pip install instaloader==4.13.1` → run `scripts/fetch_instagram.py` → appends today's count to `data/instagram.json`
2. `node scripts/inject.js` → `firebase deploy --only hosting`
3. Commits the updated `data/instagram.json` back to `main`

**Data format** (`data/instagram.json`):
```json
{
  "hankcuratesfilms": [{"date": "2026-06-18", "count": 1234}],
  "hanklosesweight":  [{"date": "2026-06-18", "count": 567}]
}
```

**GitHub secrets required** (one-time setup):
- `FIREBASE_TOKEN` — from `firebase login:ci`
- The six Firebase env vars listed above

**First run:** trigger manually via GitHub Actions → Actions → "Instagram Tracker" → Run workflow.

## Reboot

The `reboot` tab in `schedule.html` is a 50-day, 20-minute daily habit plan starting 2026-10-26 (`RB_START`). Days 1–49 are seven week-long blocks (`RB_BLOCKS`). Each block is the same workout all week, and the work seconds per interval rise every day (`work[0..6]`). Day 50 is a check-in that repeats Day 1. Moves live in `RB_MOVES`. A move is tagged NEW the first time a block uses it. The plan is knee- and lower-back-friendly by design: no sit-ups, no deep squats, and no jumping before block 6 (which has no-jump fallbacks). Daily targets are 10,000 steps and 1,500 kcal.

## India

Map geometry is regenerated (rarely — only if borders change) from an India TopoJSON with a `states` object, e.g. `topojson/india.json` from github.com/udit-001/india-maps-data:

```bash
node scripts/build_india_map.js <india.topo.json>   # writes data/india-map.json
```

Election results are deliberately static (no runtime or scheduled fetching). Each `assembly` entry's seats must sum to that state's `mla`, and each Lok Sabha entry to its `ls`. A row's optional `bloc` is the pre-poll alliance in that state; parties without a `color` in the `parties` table render grey in the seat bars. `assemblyHistory` holds each legislature's last five Assembly elections (newest first; the first entry's year must match its `assembly` year): the CM sworn in afterwards, the two largest parties' seats and the house size then (e.g. 294 for undivided Andhra Pradesh, 87 for pre-2019 J&K). `lokSabhaHistory` holds the last five general elections, and `lokSabhaStateHistory` each state/UT's seats by party in each of them (pre-2014 Andhra Pradesh is undivided with 42 seats; pre-2024 J&K has 6 seats including Ladakh, so Ladakh's own past entries are excluded when summing nationally — each year must still total 543 with the official BJP/INC counts). `upcoming` holds each legislature's next expected election (from its five-year term) and the next Lok Sabha; refresh it after each state votes. The "Power changes" map mode counts changes in the CM's party across `assemblyHistory`. The All-India view sums the Lok Sabha entries and groups them using `lokSabha.blocs` (alliances as of the 2024 election).

State names in `data/india-states.json` must match the TopoJSON's `st_nm`. Label collisions are tuned in `india.html` via `CALLOUT`, `NUDGE` and `CAP_POS`.

## Minute Cryptic

`cryptic.html` replays every daily [Minute Cryptic](https://www.minutecryptic.com) clue from #1 (2024-06-26). The next clue only unlocks once the current one is solved or revealed.

**Refreshing clues** (manual, needs `yt-dlp` on PATH):

```bash
python3 scripts/fetch_cryptic.py
```

It merges two public sources by clue number:
- Community clue-chart Google Sheet — answer, enumeration, `[fodder]`-marked clue, wordplay breakdown per type, plus its indicator-chart tab
- Official YouTube channel titles (`Minute Cryptic <n>: <clue> (<enum>)`) — official wording, enumeration, walkthrough video ids

YouTube wording wins unless the clue number is in `KEEP_SHEET_WORDING`; YouTube enumeration is ignored when it doesn't fit the answer. Dates are derived as #1 + (n−1) days. Disagreements print as `WARN` lines. Each clue's `hl` holds fodder / indicator / definition character spans over the displayed wording, powering the pick-any hint menu; the definition span is inferred (free words at the clue's start or end), so treat it as best-effort. "Cryptic Clue #N" videos are a separate pre-launch series and are deliberately not matched.
